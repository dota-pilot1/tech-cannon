# 배포 트러블슈팅 이력

## 2026-03-27: AWS 환경 변수 누락으로 인한 백엔드 시작 실패

### 문제 상황

백엔드 JAR 파일을 EC2에 배포하고 실행했을 때 애플리케이션이 시작되지 않는 문제가 발생했습니다.

### 에러 메시지

```
Caused by: java.lang.NullPointerException: Access key ID cannot be blank.
at software.amazon.awssdk.auth.credentials.AwsBasicCredentials.create(AwsBasicCredentials.java:78)
at com.mapo.palantier.config.S3Config.s3Presigner(S3Config.java:39)
```

### 원인 분석

1. **S3Config 빈 초기화 실패**:
   - Spring Boot 애플리케이션이 시작될 때 `S3Config` 클래스에서 `S3Presigner` 빈을 생성하려고 시도
   - AWS 자격증명(Access Key ID, Secret Access Key)이 필요

2. **환경 변수 누락**:
   - `application.yml`에서 `${AWS_ACCESS_KEY_ID:}` 형태로 환경 변수 참조
   - EC2 인스턴스에서 애플리케이션 실행 시 해당 환경 변수가 설정되지 않음
   - 기본값이 빈 문자열이어서 AWS SDK에서 예외 발생

3. **로컬과 프로덕션 환경 차이**:
   - 로컬 개발 환경: `.env` 파일에 AWS 자격증명 설정됨
   - EC2 프로덕션 환경: 환경 변수가 설정되지 않은 상태로 JAR 실행

### 해결 방법

**시작 스크립트를 생성하여 환경 변수 포함**:

1. 로컬에서 `start-backend.sh` 스크립트 생성:

```bash
#!/bin/bash
# 기존 프로세스 종료
pkill -f 'java -jar' || true
sleep 2

# AWS S3 환경 변수 설정
export AWS_ACCESS_KEY_ID=<YOUR_AWS_ACCESS_KEY_ID>
export AWS_SECRET_ACCESS_KEY=<YOUR_AWS_SECRET_ACCESS_KEY>
export AWS_S3_BUCKET_NAME=hibot-docu
export AWS_S3_REGION=ap-northeast-2

# 애플리케이션 시작
nohup java -jar /home/ubuntu/parantier-api-0.0.1-SNAPSHOT.jar \
    --spring.profiles.active=prod \
    > /home/ubuntu/app.log 2>&1 &

echo "Application started. PID: $!"
```

2. 스크립트를 EC2에 업로드:
```bash
scp -i "/Users/terecal/dxline-container/hibot-d-server-key 복사본.pem" \
    /tmp/start-backend.sh \
    ubuntu@43.200.241.26:/home/ubuntu/
```

3. SSH로 스크립트 실행:
```bash
ssh -i "/Users/terecal/dxline-container/hibot-d-server-key 복사본.pem" \
    ubuntu@43.200.241.26 \
    "bash /home/ubuntu/start-backend.sh"
```

### 결과

- 애플리케이션이 정상적으로 시작됨 (PID: 560614)
- S3Presigner 빈이 성공적으로 초기화됨
- 헬스체크 정상: `{"groups":["liveness","readiness"],"status":"UP"}`

### 교훈 및 권장사항

1. **환경 변수 체크리스트 작성**: 배포 전에 필요한 모든 환경 변수 확인
2. **시작 스크립트 사용**: 환경 변수를 포함한 시작 스크립트를 표준화
3. **로컬 테스트**: 프로덕션과 동일한 환경 변수 설정으로 로컬에서 테스트
4. **문서화**: `배포_가이드.md`에 환경 변수 설정 방법 명시

## 2026-03-27: SSH PEM 파일 경로 문제

### 문제 상황

배포 가이드에 명시된 PEM 파일 경로로 SSH 접속 시 `Permission denied (publickey)` 에러 발생

### 원인

- 배포 가이드에 명시된 경로: `/Users/terecal/mapo-palantier-project/배포 가이드/hibot-d-server-key.pem`
- 실제 작동하는 PEM 파일 경로: `/Users/terecal/dxline-container/hibot-d-server-key 복사본.pem`
- PEM 파일이 여러 위치에 복사되어 있었고, 일부 파일은 유효하지 않음

### 해결 방법

1. 올바른 PEM 파일 경로 확인:
```bash
/Users/terecal/dxline-container/hibot-d-server-key 복사본.pem
```

2. 배포 가이드 문서 업데이트:
   - 모든 SSH/SCP 명령어의 PEM 파일 경로를 올바른 경로로 수정
   - `AWS_인프라_정보.md`의 PEM 파일 위치 업데이트

3. PEM 파일 권한 확인:
```bash
chmod 400 "/Users/terecal/dxline-container/hibot-d-server-key 복사본.pem"
```

### 교훈

- PEM 파일 경로를 한 곳에서 관리 (변수 또는 설정 파일)
- 배포 문서 작성 시 실제 사용하는 파일 경로를 정확히 기록
- PEM 파일을 여러 곳에 복사하지 않고 한 곳에서 관리

## 2026-03-27: 프론트엔드 빌드 에러 - 사용하지 않는 import

### 문제 상황

프론트엔드 빌드 시 TypeScript 컴파일 에러 발생

### 에러 메시지

```
src/pages/issues/IssuesPage.tsx(29,101): error TS6133: 'useUpdateIssuePriority' is declared but its value is never read.
```

### 원인

- 이전 개발 과정에서 `useUpdateIssuePriority` 훅을 import했지만 실제로 사용하지 않음
- 우선순위 업데이트 기능을 다른 방식으로 구현하면서 해당 훅이 불필요해짐

### 해결 방법

`IssuesPage.tsx`에서 사용하지 않는 import 제거:

```typescript
// Before:
import { useIssues, useIssue, useUpdateIssue, useCreateIssue, useDeleteIssue, useUpdateIssueStatus, useUpdateIssuePriority } from '@/features/issue/hooks/useIssues'

// After:
import { useIssues, useIssue, useUpdateIssue, useCreateIssue, useDeleteIssue, useUpdateIssueStatus } from '@/features/issue/hooks/useIssues'
```

### 결과

- 빌드 성공
- 번들 크기: 584.86 kB (gzipped)

### 교훈

- 개발 중 사용하지 않는 import는 즉시 제거
- ESLint 설정에 `no-unused-vars` 규칙 활성화 권장
- 빌드 전 로컬에서 `npm run build` 실행하여 에러 사전 확인
