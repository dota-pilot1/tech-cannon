---

## 개요

| 항목 | 내용 |
|------|------|
| 메뉴명 | Subutai AI |
| 경로 | `/subutai` |
| 핵심 개념 | 전용 문서 DB → AI 컨텍스트 → 챗봇 응답 → 히스토리 기록 |

## 중요 질문 검토

### Q1. UI 하드코딩으로 먼저 구현하는 게 맞나?

**→ 맞다. 이게 제일 현실적인 순서다.**

이유:
- AI 연동보다 레이아웃/UX를 먼저 확정하는 게 나중에 수정 비용이 낮음
- mock 데이터로 UI 검증 → API 연동 → AI 연동 순서가 안전
- 백엔드 API, OpenAI 연동은 UI 확정 후 붙이는 게 훨씬 효율적

**Phase 1 (하드코딩 UI)**
- 문서 패널: 더미 카테고리/문서 목록
- 챗봇 패널: 더미 대화 히스토리, 입력창 동작
- 레이아웃, 색상, UX 확정

**Phase 2 (API 연동)**
- 전용 문서 DB CRUD API
- 문서 조회 → 컨텍스트 조합

**Phase 3 (AI 연동)**
- 백엔드에서 OpenAI API 호출
- 히스토리 저장/조회

---

### Q2. 기존 문서 페이지 연동 vs 전용 문서 관리 페이지 분리?

**→ 전용 문서 관리 페이지를 따로 만드는 게 맞다.**

이유:

| 구분 | 기존 문서 재활용 | 전용 문서 관리 |
|------|----------------|--------------|
| 데이터 순도 | ❌ 노이즈 포함 (코드, 이미지, 링크 등) | ✅ Q&A에 최적화된 텍스트만 |
| 관리 주체 | 각 페이지에 분산 | 한 곳에서 집중 관리 |
| 업데이트 | 각 문서 수정 시 AI 컨텍스트 영향 불확실 | 명시적으로 "AI용 문서"만 업데이트 |
| 확장성 | 어려움 (청킹, 임베딩 적용 힘듦) | 청킹/임베딩 전략 적용 용이 |
| 구현 복잡도 | 각 도메인 API 전부 연결 필요 | 단일 도메인으로 단순 |

**결론: 전용 `subutai_documents` 테이블을 따로 만들고 카테고리/문서 단위로 관리**

## DB 설계 (전용 테이블)

```sql
-- 문서 카테고리
CREATE TABLE subutai_categories (
    id         BIGSERIAL PRIMARY KEY,
    name       VARCHAR(100) NOT NULL,
    order_num  INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 문서 (AI 컨텍스트용)
CREATE TABLE subutai_documents (
    id          BIGSERIAL PRIMARY KEY,
    category_id BIGINT REFERENCES subutai_categories(id) ON DELETE CASCADE,
    title       VARCHAR(200) NOT NULL,
    content     TEXT NOT NULL,       -- AI에게 전달할 순수 텍스트
    order_num   INTEGER DEFAULT 0,
    is_active   BOOLEAN DEFAULT true,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 대화 히스토리
CREATE TABLE subutai_histories (
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT NOT NULL,
    question     TEXT NOT NULL,
    answer       TEXT NOT NULL,
    doc_ids_used BIGINT[],           -- 참조된 문서 ID 목록
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 구현 Phase

### Phase 1 - UI 하드코딩 (1~2일)
- [ ] 페이지 라우트 `/subutai` 추가
- [ ] 좌우 분할 레이아웃 구현
- [ ] 문서 패널: 카테고리 펼치기/접기, 문서 체크박스 선택
- [ ] 챗봇 패널: 더미 대화 히스토리, 입력창 + 전송 버튼
- [ ] 반응형 처리 (모바일에서 탭 전환)
- [ ] DB 메뉴 추가 (`Subutai AI`, `/subutai`, HEADER)

### Phase 2 - 문서 관리 API (2~3일)
- [ ] `subutai_categories`, `subutai_documents` 테이블 생성
- [ ] 백엔드 CRUD API 구현
- [ ] 프론트 문서 패널 실데이터 연동
- [ ] 관리자용 문서 등록/수정/삭제 UI (어드민 페이지 또는 인라인)

### Phase 3 - AI 연동 (2~3일)
- [ ] `subutai_histories` 테이블 생성
- [ ] 백엔드: 선택된 문서 내용 조합 → OpenAI API 호출
- [ ] 시스템 프롬프트 설계 (문서 내용 + 질문 형식)
- [ ] 프론트 실시간 스트리밍 응답 (SSE 또는 폴링)
- [ ] 히스토리 저장 및 목록 조회

## 백엔드 API 설계

```
GET    /api/subutai/categories              카테고리 목록
POST   /api/subutai/categories              카테고리 생성 (ADMIN)
DELETE /api/subutai/categories/{id}         카테고리 삭제 (ADMIN)

GET    /api/subutai/categories/{id}/docs    특정 카테고리 문서 목록
POST   /api/subutai/docs                    문서 등록 (ADMIN)
PUT    /api/subutai/docs/{id}               문서 수정 (ADMIN)
DELETE /api/subutai/docs/{id}               문서 삭제 (ADMIN)

POST   /api/subutai/chat                    AI 질의 (문서 ID 목록 + 질문)
GET    /api/subutai/histories               내 대화 히스토리
DELETE /api/subutai/histories/{id}          히스토리 삭제
```

### AI 질의 요청 형식
```json
{
  "documentIds": [1, 3, 5],
  "question": "Spring Security 설정 방법이 궁금해요"
}
```

## 기술 스택

| 구분 | 기술 |
|------|------|
| 프론트 | React + TanStack Query (기존 스택 동일) |
| 백엔드 | Spring Boot + MyBatis (기존 스택 동일) |
| AI | OpenAI GPT-4o API |
| AI Key 관리 | EC2 `application.yml` 환경변수 (`openai.api-key`) |
| 스트리밍 | SSE (Server-Sent Events) 또는 단순 POST 응답 |

## 주의사항

- OpenAI API Key는 **절대 코드에 하드코딩 금지** → `application.yml` + GitHub Secret
- 선택 문서가 없으면 질의 불가 처리 (UX 가이드 필요)
- 컨텍스트 길이 제한: 선택 문서가 너무 많으면 토큰 초과 → 최대 선택 개수 제한 (예: 5개)
- 히스토리는 본인 것만 조회 가능
