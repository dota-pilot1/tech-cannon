# 아키텍처 페이지 구현 계획

## 현재 상태

- 단일 사이드바 (1단) — 프론트엔드 / 서버 / DevOps / 디자인 시스템 4개 탭
- 각 탭 클릭 시 본문 바로 출력
- 하드코딩된 정적 콘텐츠

---

## 목표 UI/UX

```
┌──────────┬──────────────┬────────────────────────────┐
│ 1차 사이드 │ 2차 사이드바  │ 본문                        │
│ 바        │              │                             │
│           │              │                             │
│ 🖥️ 프론트  │ · FSD 구조   │  ## FSD 구조                │
│ ⚙️ 서버    │ · 라우팅     │  [NOTE 블록]                │
│ 🚀 DevOps │ · 상태관리   │  [MMD 다이어그램 블록]        │
│ 🎨 디자인  │ · 빌드/배포  │  [DBTABLE 블록] ...         │
│           │              │                             │
└───────────┴──────────────┴────────────────────────────┘
```

- 1차 사이드바: 대분류 (프론트엔드 / 서버 / DevOps / 디자인 시스템)
- 2차 사이드바: 1차 선택 시 해당 소분류 목록 출력
- 본문: 2차 항목 클릭 시 블록 기반 문서 출력
  - 문서 관리(TaskBlockEditor)와 동일한 블록 구조 재사용
  - NOTE / MMD / FIGMA / FILE / DBTABLE / GITHUB 블록 여러 개 추가 가능
  - ADMIN: 편집 모드 / 일반: 뷰어 모드

## DB 설계

### 테이블: `architecture_categories` (1차 카테고리)

```sql
CREATE TABLE architecture_categories (
    id          BIGSERIAL PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,       -- "프론트엔드", "서버" 등
    icon        VARCHAR(50),                 -- lucide 아이콘명 "Monitor"
    emoji       VARCHAR(10),                 -- "🖥️"
    order_num   INTEGER NOT NULL DEFAULT 0,
    is_active   BOOLEAN NOT NULL DEFAULT true,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 테이블: `architecture_sections` (2차 카테고리)

```sql
CREATE TABLE architecture_sections (
    id          BIGSERIAL PRIMARY KEY,
    category_id BIGINT NOT NULL REFERENCES architecture_categories(id) ON DELETE CASCADE,
    title       VARCHAR(200) NOT NULL,       -- "FSD 구조", "라우팅" 등
    order_num   INTEGER NOT NULL DEFAULT 0,
    is_active   BOOLEAN NOT NULL DEFAULT true,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 테이블: `architecture_blocks` (본문 블록)

문서 관리의 `task_blocks` 구조와 동일한 패턴으로 설계.
하나의 섹션에 블록 여러 개 추가 가능.

```sql
CREATE TABLE architecture_blocks (
    id          BIGSERIAL PRIMARY KEY,
    section_id  BIGINT NOT NULL REFERENCES architecture_sections(id) ON DELETE CASCADE,
    block_type  VARCHAR(20) NOT NULL,        -- NOTE / MMD / FIGMA / FILE / DBTABLE / GITHUB
    content     TEXT,                        -- 블록 내용 (Lexical JSON or plain text or JSON)
    sort_order  INTEGER NOT NULL DEFAULT 0,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_by  BIGINT REFERENCES users(id)
);
```

#### block_type 종류 (문서 관리와 동일)

| block_type | 설명 | content 형식 |
|------------|------|-------------|
| NOTE | 텍스트/마크다운 | Lexical JSON |
| MMD | Mermaid 다이어그램 | mermaid 문자열 |
| FIGMA | Figma 임베드 | JSON `{ url, title }` |
| FILE | 첨부파일 링크 | JSON `{ url, filename, description }` |
| DBTABLE | DB 테이블 정의 | JSON `{ tableName, columns[] }` |
| GITHUB | GitHub 링크 | JSON `{ url, title, type }` |

## API 설계

### 조회 (인증 사용자)

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/architecture/categories` | 1차 카테고리 목록 |
| GET | `/api/architecture/categories/{id}/sections` | 2차 항목 목록 |
| GET | `/api/architecture/sections/{id}/blocks` | 해당 섹션 블록 목록 |

### 관리 (ADMIN)

| Method | Path | 설명 |
|--------|------|------|
| POST | `/api/architecture/categories` | 1차 카테고리 생성 |
| PUT | `/api/architecture/categories/{id}` | 수정 |
| DELETE | `/api/architecture/categories/{id}` | 삭제 |
| PATCH | `/api/architecture/categories/reorder` | 순서 변경 |
| POST | `/api/architecture/sections` | 2차 항목 생성 |
| PUT | `/api/architecture/sections/{id}` | 수정 |
| DELETE | `/api/architecture/sections/{id}` | 삭제 |
| PATCH | `/api/architecture/sections/reorder` | 순서 변경 |
| PUT | `/api/architecture/sections/{id}/blocks` | 블록 전체 저장 (덮어쓰기) |

## 프론트엔드 설계

### 레이아웃 구조

```
ArchitecturePage
├── CategorySidebar (1차, w-44, shrink-0)
│   └── CategoryItem × N  (클릭 시 selectedCategoryId 변경)
├── SectionSidebar (2차, w-52, shrink-0)
│   └── SectionItem × N   (클릭 시 selectedSectionId 변경)
│   └── [+ 추가] 버튼     (ADMIN only)
└── DocPanel (본문, flex-1)
    ├── [뷰어 모드] TaskBlockViewer  ← 기존 컴포넌트 재사용
    └── [편집 모드] TaskBlockEditor  ← 기존 컴포넌트 재사용
        └── 블록 추가 버튼 (NOTE / MMD / FIGMA / FILE / DBTABLE / GITHUB)
```

### 상태 관리

```typescript
const [selectedCategoryId, setSelectedCategoryId] = useState<number | null>(null);
const [selectedSectionId, setSelectedSectionId] = useState<number | null>(null);
const [isEditing, setIsEditing] = useState(false); // ADMIN only
```

### 카테고리 선택 시 동작

```
1차 클릭 → selectedCategoryId 변경 → 2차 사이드바 렌더링
2차 클릭 → selectedSectionId 변경 → 블록 목록 fetch → DocPanel 렌더링
```

### TanStack Query 훅

```typescript
// 1차 카테고리
useQuery({ queryKey: ['arch', 'categories'] })

// 2차 섹션 (1차 선택 시)
useQuery({ queryKey: ['arch', 'sections', categoryId], enabled: !!categoryId })

// 블록 목록 (2차 선택 시)
useQuery({ queryKey: ['arch', 'blocks', sectionId], enabled: !!sectionId })
```

## 구현 순서

### Phase 1: DB + 백엔드
1. PostgreSQL 테이블 3개 생성 (categories, sections, blocks)
2. MyBatis Mapper XML 작성
3. Domain / Repository / Service / Controller 구현
4. 초기 데이터 INSERT (기존 하드코딩 → DB)

### Phase 2: 프론트엔드 기본 구조
1. `architectureApi.ts` 작성
2. `CategorySidebar` 컴포넌트
3. `SectionSidebar` 컴포넌트
4. `DocPanel` (뷰어 모드) — `TaskBlockViewer` 재사용
5. `ArchitecturePage` 레이아웃 재조립

### Phase 3: ADMIN 편집 기능
1. 편집/저장 버튼 (ADMIN only)
2. `TaskBlockEditor` 재사용 — 블록 추가/삭제/수정
3. 카테고리 / 섹션 CRUD UI
4. 순서 변경 (drag & drop — 기존 dnd-kit 재사용)
