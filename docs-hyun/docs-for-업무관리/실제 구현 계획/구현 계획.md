# 업무 관리 구현 계획 (mapo-palantier-project)

## 1. 개요

이슈 관리(`/issues`)와 동일한 **좌우 분할 레이아웃** 형태로 업무 관리를 구현한다.

| 항목 | 이슈 관리 (`/issues`) | 업무 관리 (`/work`) |
|------|----------------------|---------------------|
| 목적 | 버그·문제 트래킹 | 업무 등록·진행 추적 |
| 분류 | category (COMMON/BUG 등) | workType (FEATURE/QA/COMMON) |
| 상태 | OPEN / IN_PROGRESS / CLOSED | TODO / IN_PROGRESS / DONE / HOLD |
| 우선순위 | LOW / MEDIUM / HIGH / CRITICAL | 동일 |
| 담당자 | assigneeId 단일 | assigneeId (users 테이블 FK) |
| 요청자 | authorId (작성자) | reporterId (요청자) 별도 분리 |
| 마감일 | 없음 | dueDate 추가 |
| 체크리스트 | ✅ | ✅ (동일 구조) |
| 이미지 첨부 | ✅ | ✅ (동일 구조) |
| 마인드맵 | ✅ | ✅ (동일 구조) |
| DB 테이블 | ✅ | ✅ (동일 구조) |
| 하위 이슈 | ✅ SubIssue | ❌ (미구현 - 범위 밖) |
| 채팅 | ✅ WebSocket | ❌ (미구현 - 범위 밖) |
| 연결 이슈 | ❌ | ✅ linked_issues (이슈와 FK 연결) |
| 그리드 | AG Grid | AG Grid (동일) |

---

## 2. 기술 스택 (이슈 관리와 동일)

- **백엔드**: Spring Boot 3, MyBatis XML Mapper, PostgreSQL, Flyway
- **프론트**: TanStack Router, TanStack Query, AG Grid, Shadcn UI, Tailwind CSS
- **인증**: JWT (`Authentication` 객체로 현재 사용자 추출)
- **이미지**: S3 Presigned URL 업로드 (기존 `/api/upload` 활용)

## 4. DB 설계

### 4-1. Flyway 마이그레이션 파일

파일명: `V13__create_work_tables.sql`

```sql
-- 업무 (메인)
CREATE TABLE works (
    id              BIGSERIAL PRIMARY KEY,
    title           VARCHAR(255) NOT NULL,
    content         TEXT,
    work_type       VARCHAR(20)  NOT NULL DEFAULT 'COMMON',  -- FEATURE | QA | COMMON
    status          VARCHAR(20)  NOT NULL DEFAULT 'TODO',    -- TODO | IN_PROGRESS | DONE | HOLD
    priority        VARCHAR(20)  NOT NULL DEFAULT 'MEDIUM',  -- LOW | MEDIUM | HIGH | CRITICAL
    reporter_id     BIGINT       NOT NULL REFERENCES users(id),
    assignee_id     BIGINT       REFERENCES users(id),
    organization_id BIGINT       REFERENCES organization(id),
    due_date        DATE,
    order_num       INTEGER,
    is_archived     BOOLEAN      NOT NULL DEFAULT FALSE,
    created_at      TIMESTAMP    NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP    NOT NULL DEFAULT NOW()
);

-- 체크리스트
CREATE TABLE work_checklists (
    id          BIGSERIAL PRIMARY KEY,
    work_id     BIGINT       NOT NULL REFERENCES works(id) ON DELETE CASCADE,
    content     VARCHAR(500) NOT NULL,
    is_checked  BOOLEAN      NOT NULL DEFAULT FALSE,
    image_url   TEXT,
    image_filename VARCHAR(255),
    order_num   INTEGER      NOT NULL DEFAULT 0,
    created_at  TIMESTAMP    NOT NULL DEFAULT NOW()
);

-- 이미지
CREATE TABLE work_images (
    id          BIGSERIAL PRIMARY KEY,
    work_id     BIGINT        NOT NULL REFERENCES works(id) ON DELETE CASCADE,
    url         TEXT          NOT NULL,
    filename    VARCHAR(255)  NOT NULL,
    file_type   VARCHAR(100),
    created_at  TIMESTAMP     NOT NULL DEFAULT NOW()
);

-- 마인드맵
CREATE TABLE work_mindmaps (
    id          BIGSERIAL PRIMARY KEY,
    work_id     BIGINT        NOT NULL REFERENCES works(id) ON DELETE CASCADE,
    title       VARCHAR(255),
    content     TEXT          NOT NULL DEFAULT '',
    order_num   INTEGER       NOT NULL DEFAULT 0,
    created_at  TIMESTAMP     NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMP     NOT NULL DEFAULT NOW()
);

-- DB 테이블 첨부
CREATE TABLE work_dbtables (
    id          BIGSERIAL PRIMARY KEY,
    work_id     BIGINT        NOT NULL REFERENCES works(id) ON DELETE CASCADE,
    title       VARCHAR(255),
    table_info  JSONB         NOT NULL DEFAULT '{}',
    order_num   INTEGER       NOT NULL DEFAULT 0,
    created_at  TIMESTAMP     NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMP     NOT NULL DEFAULT NOW()
);

-- 연결 이슈 (이슈 관리의 issues 테이블과 FK)
CREATE TABLE work_linked_issues (
    id          BIGSERIAL PRIMARY KEY,
    work_id     BIGINT        NOT NULL REFERENCES works(id) ON DELETE CASCADE,
    issue_id    BIGINT        NOT NULL REFERENCES issues(id) ON DELETE CASCADE,
    created_at  TIMESTAMP     NOT NULL DEFAULT NOW(),
    UNIQUE (work_id, issue_id)
);

-- 인덱스
CREATE INDEX idx_works_reporter_id   ON works(reporter_id);
CREATE INDEX idx_works_assignee_id   ON works(assignee_id);
CREATE INDEX idx_works_status        ON works(status);
CREATE INDEX idx_works_work_type     ON works(work_type);
CREATE INDEX idx_works_due_date      ON works(due_date);
CREATE INDEX idx_works_is_archived   ON works(is_archived);
```

export type WorkType     = 'FEATURE' | 'QA' | 'COMMON'
export type WorkStatus   = 'TODO' | 'IN_PROGRESS' | 'DONE' | 'HOLD'
export type WorkPriority = 'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL'

  id: number
  title: string
  content: string
  workType: WorkType
  status: WorkStatus
  priority: WorkPriority
  reporterId: number
  reporterName: string
  assigneeId: number | null
  assigneeName: string | null
  dueDate: string | null       // 'YYYY-MM-DD'
  orderNum: number | null
  isArchived: boolean
  createdAt: string
  updatedAt: string
}

export interface CreateWorkRequest {
  title: string
  content: string
  workType: WorkType
  status: WorkStatus
  priority: WorkPriority
  assigneeId?: number | null
  dueDate?: string | null
}

export interface WorkFilters {
  workType?: WorkType
  status?: WorkStatus
  priority?: WorkPriority
  assigneeId?: number
  keyword?: string
  sortBy?: 'created' | 'priority' | 'status' | 'dueDate'

}
