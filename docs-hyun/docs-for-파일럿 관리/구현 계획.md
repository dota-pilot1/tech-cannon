# 파일럿 관리 구현 계획

## 개요

업무 관리(`/work`)와 거의 동일한 구조로 파일럿 프로젝트 문서화 페이지 구현  
기술 주제별로 파일럿 프로젝트를 등록하고 공유하는 공간

---

## 업무 관리와 차이점

| 항목 | 업무 관리 | 파일럿 관리 |
|------|----------|------------|
| 라우트 | `/work` | `/pilot` |
| 메인 엔티티 | `Work` | `Pilot` |
| 타입 분류 | FEATURE / QA / COMMON | 기술 주제 20개 |
| 상태 | TODO / IN_PROGRESS / DONE / HOLD | 동일 |
| 우선순위 | LOW~CRITICAL | 동일 |
| 부가 기능 | 이미지 / MMD / DB테이블 / 피그마 / 채팅 / 연결 이슈 | 동일 |

---

## 구현 순서

### Step 1. 백엔드 DB

```sql
-- V17__create_pilot_tables.sql
-- works 테이블 구조 그대로 복사 → pilots
CREATE TABLE pilots (
    id              BIGSERIAL PRIMARY KEY,
    title           VARCHAR(255) NOT NULL,
    content         TEXT,
    topic           VARCHAR(30)  NOT NULL DEFAULT 'React',  -- 기술 주제
    status          VARCHAR(20)  NOT NULL DEFAULT 'TODO',
    priority        VARCHAR(20)  NOT NULL DEFAULT 'MEDIUM',
    reporter_id     BIGINT       NOT NULL REFERENCES users(id),
    assignee_id     BIGINT       REFERENCES users(id),
    due_date        DATE,
    order_num       INTEGER,
    is_archived     BOOLEAN      NOT NULL DEFAULT FALSE,
    created_at      TIMESTAMP    NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP    NOT NULL DEFAULT NOW()
);

-- 부속 테이블 (work_* 그대로 pilot_* 로)
CREATE TABLE pilot_images     (...);  -- work_images 동일
CREATE TABLE pilot_checklists (...);  -- work_checklists 동일
CREATE TABLE pilot_mindmaps   (...);  -- work_mindmaps 동일
CREATE TABLE pilot_dbtables   (...);  -- work_dbtables 동일
CREATE TABLE pilot_figmas     (...);  -- work_figmas 동일
CREATE TABLE pilot_messages   (...);  -- work_messages 동일
```

### Step 2. 백엔드 Java

```

### Step 3. 프론트엔드

work 관련 파일 구조 그대로 복사 → pilot 으로 rename

```

│   └── types/pilot.ts               (work.ts → workType → topic)

```

### Step 4. 라우트 등록

  getParentRoute: () => rootRoute,

```

## 핵심 변경 포인트 (work → pilot)

| work | pilot |
|------|-------|
| `WorkType` (FEATURE/QA/COMMON) | `PilotTopic` (React/Java/DB...) |
| 타입 필터 버튼명 | 기술 주제명으로 변경 |
| "새 업무" 버튼 | "새 파일럿" 버튼 |
| `/api/works` | `/api/pilots` |
| `work_*` 테이블 | `pilot_*` 테이블 |

---

## 구현 우선순위

1. **DB + 백엔드** - SQL 마이그레이션 → Java 도메인/매퍼/컨트롤러
2. **프론트 타입/API** - pilot.ts, pilotApi.ts
3. **프론트 훅** - usePilots.ts 외
4. **PilotPage.tsx** - WorkPage.tsx 복사 후 topic 필드로 수정
5. **라우트 + 메뉴 등록**

---

## 예상 작업량

- 백엔드: 약 2~3시간 (work 패키지 복사 + 네이밍 변경)
- 프론트: 약 1~2시간 (work 파일 복사 + 타입 수정)
- 총 예상: **반나절** 이내 완료 가능
