# 재사용 가능한 핵심 구성요소

> 새 SI 프로젝트 시작 시 TechCannon에서 그대로 가져다 쓸 수 있는 구성요소 목록입니다.
> 실제 코드 위치와 함께 정리했습니다.

---

## 백엔드

### 1. JWT 인증 체계 (즉시 재사용 가능)

가장 완성도가 높은 부분입니다. 3개 파일로 구성됩니다.

| 파일 | 역할 |
|------|------|
| `config/JwtTokenProvider.java` | Access/Refresh 토큰 생성, 검증, 파싱 |
| `config/JwtAuthenticationFilter.java` | 요청마다 JWT 검증 → `request.setAttribute("userId", userId)` |
| `config/SecurityConfig.java` | GET 공개, POST/PUT/DELETE 인증 필요, ADMIN 경로 분리 |

**핵심 패턴 — Controller가 인증을 모름**
```java
// Controller에서 JWT 내부 구조를 몰라도 됨
@PostMapping
public ResponseEntity<Long> create(
    @RequestBody @Valid SomeRequest request,
    @RequestAttribute("userId") Long userId   // Filter가 넣어준 값
) { ... }
```

새 프로젝트 적용 시 `application.yml`의 `jwt.secret`, `jwt.access-token-expiration` 값만 변경하면 됩니다.

### 2. 예외 처리 체계 (즉시 재사용 가능)

`common/exception/` 폴더 전체를 복사하면 됩니다.

```
common/exception/
├── ErrorCode.java              ← 전 도메인 에러코드 enum (HTTP 상태 포함)
├── GlobalExceptionHandler.java ← 전역 예외 → 일관된 JSON 응답
├── ResourceNotFoundException.java  ← 404
├── ForbiddenException.java         ← 403
├── DuplicateException.java         ← 409
├── AuthenticationException.java    ← 401
└── ...
```

**응답 포맷 일관성**
```json
{
  "errorCode": "TASK_POST_NOT_FOUND",
  "message": "게시글을 찾을 수 없습니다",
  "timestamp": "2025-01-01T00:00:00",
  "path": "/api/tasks/posts/999"
}
```

새 도메인 추가 시 `ErrorCode`에 에러코드만 추가하면 `GlobalExceptionHandler`는 추가 작업 없이 자동으로 처리합니다.

### 3. DDD 4계층 구조 — `task` / `wiki` 도메인 (패턴 참고)

신규 도메인 추가 시 `task` 도메인 구조를 그대로 복사해서 이름만 바꾸면 됩니다.

```
(신규도메인)/
├── presentation/
│   ├── (도메인)Controller.java       ← @Valid, @RequestAttribute("userId")
│   └── dto/
│       ├── (도메인)Request.java      ← @NotBlank, @NotNull 최소 검증
│       └── (도메인)Response.java     ← 도메인 객체 직접 노출 금지
├── application/
│   └── (도메인)Service.java          ← Repository 인터페이스만 의존
├── domain/
│   ├── (도메인).java                 ← @Getter @Builder + 팩토리 메서드
│   └── (도메인)Repository.java       ← 인터페이스 (DIP)
└── infrastructure/
    ├── (도메인)Mapper.java            ← @Mapper MyBatis
    └── (도메인)RepositoryImpl.java    ← 인터페이스 구현체
```

**체크리스트 — 새 도메인 추가 시**
- [ ] `domain/` 에 Repository 인터페이스 선언
- [ ] `infrastructure/` 에 Mapper + RepositoryImpl 생성
- [ ] `application/` Service는 Repository 인터페이스만 주입
- [ ] `presentation/` Controller에 `@RequestAttribute("userId")` 사용
- [ ] Response DTO 분리 (도메인 객체 직접 반환 금지)
- [ ] `ErrorCode`에 해당 도메인 404 에러코드 추가

### 4. MyBatis ResultMap → DTO 직접 매핑 패턴

JOIN 결과를 도메인 객체에 담지 않고 Response DTO에 직접 매핑하는 패턴입니다.
`authorName` 같은 다른 컨텍스트 데이터가 도메인 객체를 오염시키지 않습니다.

```xml
<!-- 도메인 객체가 아닌 DTO를 ResultMap 타겟으로 지정 -->
<resultMap id="TaskPostSummaryResultMap"
           type="com.mapo.palantier.task.presentation.dto.TaskPostSummary">
    <result property="authorName" column="author_name"/>  <!-- JOIN 결과 -->
    ...
</resultMap>

<select id="findAll" resultMap="TaskPostSummaryResultMap">
    SELECT p.*, u.username as author_name
    FROM task_posts p JOIN users u ON p.author_id = u.id
    WHERE p.deleted_at IS NULL
</select>
```

### 5. Role + Authority 이중 권한 체계

단순 Role 체크 외에 세밀한 Authority 기반 권한 제어가 필요한 프로젝트에 유용합니다.

```
user.role = ROLE_ADMIN | ROLE_USER      ← 거친 권한 (메뉴 접근 등)
user.authorities = ["READ_TASK", ...]   ← 세밀한 권한 (기능별 제어)
```

JWT 발급 시 개인 권한 + 조직 권한을 합산해서 토큰에 포함합니다.

## 프론트엔드

### 1. Axios 클라이언트 + JWT 자동 첨부

`shared/api/client.ts` — 복사해서 `baseURL`만 변경하면 됩니다.

```typescript
export const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_URL,
});

// 요청마다 JWT 자동 첨부
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem("accessToken");
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// 401 응답 시 자동 로그아웃 처리
apiClient.interceptors.response.use(
  (res) => res,
  (err) => {
    if (err.response?.status === 401) {
      authStore.setState((s) => ({ ...s, isAuthenticated: false }));
    }
    return Promise.reject(err);
  }
);
```

### 2. 인증 스토어 + 라우트 가드

`entities/user/model/authStore.ts` + `app/routes/index.tsx`

```typescript
// 로그인 필요 라우트
const requireAuth = async () => {
  await waitForRestore();
  if (!authStore.state.isAuthenticated) {
    throw redirect({ to: "/login" });
  }
};

// 관리자 전용 라우트
const requireAdmin = async () => {
  await requireAuth();
  if (authStore.state.user?.role !== "ROLE_ADMIN") {
    throw redirect({ to: "/" });
  }
};
```

새 프로젝트에서 라우트 추가 시 `beforeLoad: () => requireAuth()` 한 줄로 인증 가드가 적용됩니다.

### 3. TanStack Query 훅 패턴

`features/task/hooks/useTask.ts`의 패턴을 신규 도메인에 그대로 복사합니다.

```typescript
// 조회
export const useTaskFolders = () =>
  useQuery({ queryKey: ["taskFolders"], queryFn: taskApi.getFolders });

// 뮤테이션 + 캐시 무효화
export const useCreateFolderMutation = (onSuccess?: () => void) =>
  useMutation({
    mutationFn: taskApi.createFolder,
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["taskFolders"] });
      onSuccess?.();
    },
  });
```

## CI/CD 파이프라인

`.github/workflows/` 폴더 전체를 복사 후 GitHub Secrets만 설정하면 됩니다.

| Secret | 설명 |
|--------|------|
| `EC2_SSH_PRIVATE_KEY` | EC2 PEM 키 내용 |
| `EC2_HOST` | EC2 IP |
| `EC2_USER` | ubuntu |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD` | DB 접속 정보 |
| `JWT_SECRET` | JWT 서명 키 |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | AWS 자격증명 |
| `AWS_S3_BUCKET_NAME` | S3 버킷명 |
| `AWS_CLOUDFRONT_DISTRIBUTION_ID` | CloudFront ID |
| `OPENAI_API_KEY` | AI 기능 사용 시 |

push to main 시 변경된 경로에 따라 백엔드/프론트엔드 배포가 자동으로 트리거됩니다.
