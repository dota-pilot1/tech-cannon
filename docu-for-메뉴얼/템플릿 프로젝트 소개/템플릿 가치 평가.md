# TechCannon — SI 템플릿 프로젝트 가치 평가

> 이 문서는 TechCannon 프로젝트가 SI 프로젝트의 프로토타입/보일러플레이트/템플릿으로서
> 어떤 가치를 가지는지 객관적으로 평가한 문서입니다.

---

## 한 줄 요약

> **"팀 내부 신규 프로젝트 시작점으로는 충분한 가치가 있다.
> 단, 외부 공개 템플릿으로 쓰려면 구조 일관성 확보와 테스트 코드가 필요하다."**

---

## 용도별 평가

| 용도 | 평가 | 이유 |
|------|------|------|
| 팀 내부 레퍼런스 | ✅ 충분히 가치 있음 | 실제 동작하는 인증/권한/예외처리/배포 파이프라인 완비 |
| 신규 프로젝트 시작점 | ✅ 가져다 쓸 수 있음 | JWT, DDD 4계층, CI/CD 구조를 그대로 복사 가능 |
| SI 제안서 첨부 | ⚠️ 조건부 가능 | 일관성 있는 도메인 몇 개만 추려서 제시 |
| 외부 공개 보일러플레이트 | ❌ 아직 이른 단계 | 구조 불일관, 테스트 없음, 중복 코드 |

## ✅ 강점 — 대부분의 SI 프로젝트가 갖추지 못한 것들

### 백엔드

#### 1. DDD 4계층 아키텍처 일관성 (핵심 도메인)
`user`, `task`, `wiki`, `workspace`, `authority` 도메인은
Presentation → Application → Domain ← Infrastructure 단방향 의존을 완전히 구현했습니다.

```
task/
├── presentation/   TaskPostController.java     ← @RequestAttribute("userId")
├── application/    TaskPostService.java         ← Repository 인터페이스만 의존
├── domain/         TaskPost.java, TaskPostRepository.java (인터페이스)
└── infrastructure/ TaskPostMapper.java, TaskPostRepositoryImpl.java
```

#### 2. 완성된 인증/인가 체계
- JWT Access Token + Refresh Token 이중 구조
- Role 기반 (`ROLE_USER`, `ROLE_ADMIN`) + Authority 기반 이중 권한 체계
- `JwtAuthenticationFilter` → `request.setAttribute("userId")` → `@RequestAttribute("userId")`
  Controller가 인증 방식을 전혀 몰라도 되는 구조

#### 3. 도메인 예외 처리 체계 완성

```java
// 404
throw new ResourceNotFoundException(ErrorCode.TASK_POST_NOT_FOUND);
// 403
throw new ForbiddenException(ErrorCode.FORBIDDEN_UPDATE);
// 409
throw new DuplicateException(ErrorCode.DUPLICATE_ROLE);
```

`GlobalExceptionHandler` 하나로 전 도메인 예외를 일관된 JSON 포맷으로 처리합니다.

#### 4. Repository 패턴 (DIP 준수)
Service는 MyBatis `@Mapper`를 직접 모르고,
`domain` 레이어의 인터페이스만 바라봅니다.
DB 기술이 MyBatis → JPA로 바뀌어도 Service 코드는 변경 없음.

#### 5. Rich Domain Model
```java
// 팩토리 메서드
TaskPost.create(folderId, title, authorId)
TaskFolder.withUpdated(name, parentId, sortOrder)
User.withRole(role)

// 상태 변경 메서드
user.deactivate()
user.activate()
user.isAdmin()
```

#### 6. Response DTO / Request DTO 분리
- `@Valid` + `@NotBlank`, `@NotNull`, `@Email`, `@Size(min)` 최소 검증
- 도메인 객체를 외부에 직접 노출하지 않음
- MyBatis ResultMap → Response DTO 직접 매핑 (authorName Bounded Context 침투 해결)

#### 7. CI/CD 파이프라인 완성
```
git push to main
  ├── parantier-api/** 변경 시 → GitHub Actions → Gradle 빌드 → EC2 배포 → 헬스체크
  └── parantier-front/** 변경 시 → GitHub Actions → Vite 빌드 → S3 업로드 → CloudFront 무효화
```

### 프론트엔드

#### 1. TanStack 풀스택 상태 관리
- `TanStack Query` — 서버 상태 (API 캐싱, 낙관적 업데이트)
- `TanStack Store` — 클라이언트 상태 (인증 정보)
- `TanStack Router` — 타입 안전 라우팅 + 라우트 레벨 인증 가드
- `TanStack Form` — 폼 검증

#### 2. 컴포넌트 분리 원칙
`renderXxx()` 안티패턴 제거, IIFE 인라인 렌더링 제거,
모든 UI 단위가 독립 컴포넌트(`<TaskFolderItem />`, `<TaskSearchResult />` 등)로 분리.

#### 3. 블록 에디터 시스템
`NOTE(Lexical)`, `MMD(Mermaid)`, `FIGMA`, `FILE(S3)`, `DBTABLE`, `GITHUB`
6가지 블록 타입을 지원하는 에디터 + 뷰어 완성.

#### 4. 다크모드 시맨틱 토큰 시스템
하드코딩된 색상 없이 `bg-background`, `text-foreground` 등
CSS 변수 기반 시맨틱 토큰으로 라이트/다크 모드를 완전히 지원.

## ❌ 한계 — 개선이 필요한 부분

### 1. 도메인 간 구조 일관성 부족 (가장 큰 문제)

핵심 도메인(`user`, `task`, `wiki`)은 DDD 4계층이지만,
`chat`, `bookmark`, `dashboard`는 레이어 구분 없이 flat 구조입니다.

```
// DDD 적용됨
task/ → application/ domain/ infrastructure/ presentation/

// DDD 미적용
chat/ → ChatController.java, ChatRoomService.java, ChatMessage.java (혼재)
```

템플릿으로 참고하는 사람이 어느 게 기준인지 혼란스러울 수 있습니다.

### 2. 중복 코드 — category/section/block 패턴

`faq`, `apidoc`, `architecture`, `core`, `frontend`, `textbook`, `subutai-faq`, `hackathon-apidoc`
8개 도메인이 동일한 패턴을 복붙했습니다. 진정한 템플릿이라면
이 패턴을 추상화해서 제공해야 합니다.

### 3. 테스트 코드 없음

Service 레이어 단위 테스트, Controller 통합 테스트가 전혀 없습니다.
SI 납품 기준으로는 치명적인 약점입니다.

### 4. 프론트 FSD 구조 불완전

`src/src` 폴더가 존재하고, `pages`, `routes`, `features`, `widgets`, `entities`의
역할 경계가 명확하지 않은 곳이 있습니다.

## 재사용 가능한 핵심 구조 목록

새 SI 프로젝트 시작 시 **그대로 가져다 쓸 수 있는 부분**입니다.

### 백엔드
| 구조 | 위치 | 설명 |
|------|------|------|
| JWT 인증 필터 | `config/JwtAuthenticationFilter.java` | userId를 request attribute로 전달 |
| JWT 토큰 프로바이더 | `config/JwtTokenProvider.java` | Access/Refresh 토큰 생성/검증 |
| 예외 처리 체계 | `common/exception/` | ErrorCode, 3종 예외 클래스, GlobalExceptionHandler |
| Security 설정 | `config/SecurityConfig.java` | GET 공개, POST/PUT/DELETE 인증 필요 |
| DDD 4계층 구조 | `task/`, `wiki/` 도메인 | 신규 도메인 추가 시 참고 기준 |
| S3 설정 | `config/S3Config.java` | AWS S3 파일 업로드 |
| WebSocket 설정 | `config/WebSocketConfig.java` | 순수 WebSocket (STOMP 미사용) |

### 프론트엔드
| 구조 | 위치 | 설명 |
|------|------|------|
| Axios 클라이언트 | `shared/api/client.ts` | JWT 자동 첨부 인터셉터 |
| 인증 스토어 | `entities/user/model/authStore.ts` | TanStack Store 기반 |
| 라우트 인증 가드 | `app/routes/index.tsx` | `requireAuth()`, `requireRole()` |
| 블록 에디터 | `features/task/components/TaskBlockEditor.tsx` | 6종 블록 타입 |
| 다크모드 설정 | `index.css`, `tailwind.config.ts` | 시맨틱 토큰 시스템 |
