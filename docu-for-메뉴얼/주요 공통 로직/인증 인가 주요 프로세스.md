# 인증/인가 주요 프로세스

## 1. 회원가입 (Signup)

```
POST /api/auth/signup
{ email, password, username }
        │
        ▼
AuthService.signup()
  1. 이메일 중복 체크 → DuplicateEmailException
  2. BCrypt 비밀번호 암호화
  3. User.createNewUser() 팩토리 메서드로 생성
  4. UserRepository.save()
        │
        ▼
201 Created { userId, email, username }
```

---

## 2. 로그인 (Login)

```
POST /api/auth/login
{ email, password }
        │
        ▼
AuthService.login()
  1. UserRepository.findByEmail() → UserNotFoundException
  2. BCrypt.matches() 비밀번호 검증 → AuthenticationException
  3. user.isActive 체크 → AccountInactiveException
  4. JwtTokenProvider.generateAccessToken(userId, email, role)
     - 개인 권한(UserAuthority) + 조직 권한(OrganizationAuthority) 합산
     - JWT Claims: { sub, userId, role, authorities[], type:"ACCESS" }
  5. JwtTokenProvider.generateRefreshToken(email)
  6. 기존 RefreshToken 삭제 → 새 RefreshToken 저장 (7일)
        │
        ▼
200 OK {
  userId, accessToken, refreshToken,
  email, username, role
}
```

---

## 3. 인증 요청 처리 (JWT Filter)

```
모든 API 요청
        │
        ▼
JwtAuthenticationFilter.doFilterInternal()
  1. Authorization 헤더 → "Bearer {token}" 추출
  2. JwtTokenProvider.validateToken(token)
     - 실패 → 401 반환 없이 그냥 통과 (SecurityConfig에서 차단)
  3. 성공 → email, role, userId 추출
  4. request.setAttribute("userId", userId)
  5. UsernamePasswordAuthenticationToken 생성
     - principal: userId (Long)
     - authorities: [SimpleGrantedAuthority(role)]
  6. SecurityContextHolder.setAuthentication()
        │
        ▼
SecurityConfig.authorizeHttpRequests()
  - 공개 경로 → 통과
  - 인증 필요 경로 → SecurityContext 확인
  - ADMIN 전용 → role 확인
```

---

## 4. 토큰 재발급 (Refresh)

```
POST /api/auth/refresh
{ refreshToken }
        │
        ▼
AuthService.refreshAccessToken()
  1. JwtTokenProvider.validateRefreshToken() 검증
  2. RefreshTokenRepository.findByToken() → DB에서 조회
  3. storedToken.isExpired() → 만료 시 삭제 후 예외
  4. UserRepository.findById()
  5. 새 AccessToken 발급
        │
        ▼
200 OK { accessToken }
```

---

## 5. 로그아웃 (Logout)

```
POST /api/auth/logout (인증 필요)
        │
        ▼
AuthService.logout(userId)
  RefreshTokenRepository.deleteByUserId(userId)
        │
        ▼
프론트엔드:
  localStorage.removeItem("accessToken")
  localStorage.removeItem("refreshToken")
  authStore 초기화
```

---

## 6. 프론트엔드 인증 복원 (새로고침 시)

```
앱 최초 마운트 (providers.tsx)
        │
        ▼
authActions.restoreAuth()
  1. localStorage에서 accessToken, refreshToken 조회
  2. 없으면 → isRestored = true (비로그인 상태)
  3. 있으면 → GET /api/auth/me 로 유저 정보 조회
  4. 성공 → JWT에서 roles, authorities 파싱 → authStore 업데이트
  5. 401/403 실패 → POST /api/auth/refresh 시도
     - 성공 → 새 토큰으로 재시도
     - 실패 → authActions.logout()
  6. 네트워크/5xx 오류 → 토큰 유지 (로그아웃 안 함)
```

## 7. 권한(Authority) 시스템

Role과 Authority 두 계층으로 관리:

```
Role (역할): ROLE_USER, ROLE_ADMIN
Authority (세부 권한): READ_WIKI, WRITE_TASK, MANAGE_USERS 등
```

```java
// JWT에 둘 다 포함
{
  "role": "ROLE_USER",
  "authorities": ["READ_WIKI", "WRITE_TASK", "READ_STUDY"]
}
```

프론트엔드 권한 체크:
```typescript
// shared/lib/permission.ts
hasRole('ROLE_ADMIN')              // 역할 체크
hasAuthority('READ_WIKI')         // 세부 권한 체크
hasAnyAuthority('READ_WIKI', 'WRITE_WIKI')  // OR 조건
hasAllAuthorities('READ', 'WRITE')           // AND 조건
```

## 8. Controller에서 사용자 정보 접근

```java
// 방법 1: @AuthenticationPrincipal (User 객체)
public ResponseEntity<?> method(@AuthenticationPrincipal User user) {
    Long userId = user.getId();
}

// 방법 2: request.getAttribute (userId만 필요할 때)
Long userId = (Long) request.getAttribute("userId");

// 방법 3: SecurityContextHolder
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
Long userId = (Long) auth.getPrincipal();
```
