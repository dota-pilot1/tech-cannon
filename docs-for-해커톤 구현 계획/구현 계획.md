# 해커톤 페이지 구현 계획

---

## ✅ 권장 구현 순서

### Step 1. DB + 백엔드 기본 CRUD (1일)
> 모든 탭 기능의 기반. 이것 없이는 아무것도 실데이터로 동작 안 함.
1. DB 테이블 생성 (`hackathon_events`, `hackathon_teams`, `hackathon_team_members`)
2. 백엔드 도메인 구조 생성 (architecture/frontend 패턴 그대로 복제)
3. 이벤트 + 팀 기본 CRUD API
4. 프론트에서 더미 데이터 → 실API 연동

### Step 2. 채팅 실시간화 (0.5일)
> 이미 `usePureWebSocket` + WebSocket 핸들러가 갖춰져 있어서 회의실 패턴 그대로 복붙 수준.
1. `hackathon_chat_messages` 테이블 생성
2. 백엔드 WebSocket 핸들러에 `hackathon-chat/{eventId}` 토픽 추가
3. 프론트 `useHackathonChat` 훅 (회의실 `useMeetingChat` 패턴 재사용)
4. 채팅 히스토리 REST API + 실시간 WS 연동

### Step 3. 카운트다운 타이머 (0.5일)
> 순수 프론트 작업. DB의 `end_at` 필드만 있으면 됨.
1. `HackathonTimer` 컴포넌트 작성 (`setInterval` 1초 업데이트)
2. 상단 요약 카드의 "남은 시간" 연동
3. 종료 시 "해커톤 종료!" 표시

### Step 4. Figma 탭 (0.5일)
> 링크 카드 형식. 가장 단순한 탭.
1. `hackathon_team_links` 테이블 생성
2. 링크 CRUD API
3. 프론트: URL 입력 → Figma 링크 카드 표시

### Step 5. Task 탭 칸반 (1일)
> 기존 `TaskBlock` 타입 재사용. `dnd-kit` 이미 프로젝트에 있음.
1. `hackathon_team_tasks` 테이블 생성
2. Task CRUD API
3. 프론트: TODO / DOING / DONE 칸반 뷰 (`dnd-kit` 드래그)

### Step 6. Issue 탭 (1일)
> 기존 `IssuesPage` 패턴 참고. AG Grid 대신 심플한 카드 리스트로 구현.
1. `hackathon_team_issues` 테이블 생성
2. Issue CRUD API
3. 프론트: 우선순위 배지 + 상태 탭 필터

### Step 7. GitHub 탭 (0.5일)
> Figma 탭과 동일 구조 (링크 카드). GitHub 레포 URL만 다름.
1. `hackathon_team_links` 테이블 공용 사용 (`link_type = 'github'`)
2. 프론트: GitHub 레포 카드 표시

### Step 8. FAQ 탭 (0.5일)
> 기존 `FaqPage` 패턴 참고. Q&A 아코디언 리스트.
1. `hackathon_team_faq` 테이블 생성
2. FAQ CRUD API
3. 프론트: 아코디언 Q&A 목록

### Step 9. 고도화 (선택)
- 팀 참가 신청 / ADMIN 승인
- 결과 발표 + 투표
- 진행률 자동 계산 (Task 완료율)
- 알림 (채팅/Task 마감/Issue 담당자)

## 📎 기존 구현 참고사항 (탭별 재사용 전략)

### 공통 패턴
| 재사용 요소 | 출처 | 해커톤 적용 방법 |
|---|---|---|
| WebSocket 채팅 | `useMeetingChat` | `useHackathonChat` 훅으로 복제, 토픽만 `hackathon-chat/{eventId}` 변경 |
| 블록 타입 시스템 | `task.types.ts` (`BlockType`, `TYPE_META`) | FAQ/Task 블록 콘텐츠 저장 방식에 활용 |
| DnD 정렬 | 아키텍처/FAQ 페이지 `dnd-kit` 패턴 | Task 칸반 드래그, FAQ 순서 변경 |
| 의존 쿼리 패턴 | FAQ 페이지 `enabled: !!selectedId` | 팀 선택 → 탭 데이터 지연 로딩 |
| Silent 뮤테이션 | IssuesPage `useCreateIssueSilent` | 자동저장/일괄저장 시 toast 없는 뮤테이션 |
| 백엔드 도메인 구조 | `frontend/apidoc` 도메인 | 동일 패턴 (domain/dto/infrastructure/application/presentation) |

### Figma 탭 → `hackathon_team_links` 공용 (link_type = 'figma')
- 링크 URL 입력 + 제목
- Figma embed 미리보기 (`<iframe>`) or 링크 카드
- 참고: `task.types.ts`의 `FileContent { url, filename, description }` 구조

### Task 탭 → 기존 `TaskBlock` + `dnd-kit` 재사용
- 칸반 3컬럼: `TODO / DOING / DONE`
- 참고: 아키텍처 페이지 `DndContext + SortableContext + arrayMove` 패턴
- 담당자 지정: 기존 `useIssueAssignees` 패턴 참고
- 카운트 포함 상태 탭: `IssuesPage` 헤더 탭 UI 그대로 적용

### Issue 탭 → `IssuesPage` 경량화 버전
- AG Grid 없이 심플 카드 리스트로 구현 (해커톤 특성상 규모 작음)
- 우선순위: `LOW / MEDIUM / HIGH` 배지 (IssuesPage `PriorityCell` 참고)
- 상태 필터 탭: `OPEN / IN_PROGRESS / CLOSED`
- 참고: `IssuesPage`의 상태탭 카운트 + 필터 드롭다운 패턴

### GitHub 탭 → `hackathon_team_links` 공용 (link_type = 'github')
- 참고: `task.types.ts`의 `GithubContent { url, title, description, type }` 구조 그대로 활용
- 레포 카드 표시 (URL, 설명, 타입 배지)

### FAQ 탭 → `FaqPage` 경량화 버전
- 3단 사이드바 없이 단일 팀 내 Q&A 아코디언
- 참고: FaqPage의 `FaqBlock` 저장 방식 (섹션 단위 PUT 전체 덮어쓰기)
- 순서 변경: FaqPage DnD 패턴 동일 적용
- 내용 작성: `TaskBlockEditor` (NOTE 블록 타입) 활용 가능

### 채팅 → `useMeetingChat` 패턴 복제
- `usePureWebSocket` 싱글톤 그대로 사용
- 토픽: `hackathon-chat/{eventId}`
- 참여자 JOIN/LEAVE 없이 메시지만 브로드캐스트
- 히스토리: `GET /api/hackathon/events/{eventId}/chat?limit=50`

## Phase 2 - DB 설계 및 백엔드 API

### 2-1. DB 테이블 설계

#### `hackathon_events` - 해커톤 이벤트
```sql
CREATE TABLE hackathon_events (
    id          BIGSERIAL PRIMARY KEY,
    title       VARCHAR(200) NOT NULL,           -- "2024 사내 해커톤"
    description TEXT,
    start_at    TIMESTAMP NOT NULL,              -- 시작 시간
    end_at      TIMESTAMP NOT NULL,              -- 종료 시간
    max_teams   INTEGER NOT NULL DEFAULT 2,      -- 최대 팀 수 (현재 2팀 제한)
    is_active   BOOLEAN NOT NULL DEFAULT true,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### `hackathon_teams` - 팀 정보
```sql
CREATE TABLE hackathon_teams (
    id          BIGSERIAL PRIMARY KEY,
    event_id    BIGINT NOT NULL REFERENCES hackathon_events(id) ON DELETE CASCADE,
    name        VARCHAR(100) NOT NULL,           -- "Team A", "Team B"
    project     VARCHAR(300),                    -- 프로젝트명
    color_theme VARCHAR(50),                     -- "blue" | "emerald"
    order_num   INTEGER NOT NULL DEFAULT 0,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### `hackathon_team_members` - 팀 멤버
```sql
CREATE TABLE hackathon_team_members (
    id       BIGSERIAL PRIMARY KEY,
    team_id  BIGINT NOT NULL REFERENCES hackathon_teams(id) ON DELETE CASCADE,
    user_id  BIGINT NOT NULL REFERENCES users(id),
    joined_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (team_id, user_id)
);
```

#### `hackathon_chat_messages` - 오픈 채팅
```sql
CREATE TABLE hackathon_chat_messages (
    id         BIGSERIAL PRIMARY KEY,
    event_id   BIGINT NOT NULL REFERENCES hackathon_events(id) ON DELETE CASCADE,
    user_id    BIGINT NOT NULL REFERENCES users(id),
    username   VARCHAR(100) NOT NULL,
    content    TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_hackathon_chat_event_id ON hackathon_chat_messages (event_id, created_at DESC);
```

#### `hackathon_team_links` - 팀별 링크 (Figma, GitHub 등)
```sql
CREATE TABLE hackathon_team_links (
    id         BIGSERIAL PRIMARY KEY,
    team_id    BIGINT NOT NULL REFERENCES hackathon_teams(id) ON DELETE CASCADE,
    link_type  VARCHAR(20) NOT NULL,             -- 'figma' | 'github' | 'notion' | 'custom'
    title      VARCHAR(200),
    url        TEXT NOT NULL,
    created_by BIGINT REFERENCES users(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### `hackathon_team_tasks` - 팀별 Task (기존 Task 연동 or 독립)
```sql
-- 옵션 1: 기존 task_posts 테이블 연동 (task_id 참조)
-- 옵션 2: 독립 테이블로 경량화
CREATE TABLE hackathon_team_tasks (
    id          BIGSERIAL PRIMARY KEY,
    team_id     BIGINT NOT NULL REFERENCES hackathon_teams(id) ON DELETE CASCADE,
    title       VARCHAR(300) NOT NULL,
    status      VARCHAR(20) NOT NULL DEFAULT 'todo',  -- todo | doing | done
    assignee_id BIGINT REFERENCES users(id),
    due_at      TIMESTAMP,
    created_by  BIGINT REFERENCES users(id),
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### `hackathon_team_issues` - 팀별 이슈
```sql
CREATE TABLE hackathon_team_issues (
    id          BIGSERIAL PRIMARY KEY,
    team_id     BIGINT NOT NULL REFERENCES hackathon_teams(id) ON DELETE CASCADE,
    title       VARCHAR(300) NOT NULL,
    content     TEXT,
    status      VARCHAR(20) NOT NULL DEFAULT 'open',  -- open | in_progress | closed
    priority    VARCHAR(10) NOT NULL DEFAULT 'medium', -- low | medium | high
    assignee_id BIGINT REFERENCES users(id),
    created_by  BIGINT REFERENCES users(id),
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### `hackathon_team_faq` - 팀별 FAQ
```sql
CREATE TABLE hackathon_team_faq (
    id         BIGSERIAL PRIMARY KEY,
    team_id    BIGINT NOT NULL REFERENCES hackathon_teams(id) ON DELETE CASCADE,
    question   TEXT NOT NULL,
    answer     TEXT,
    order_num  INTEGER NOT NULL DEFAULT 0,
    created_by BIGINT REFERENCES users(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 2-2. 백엔드 API 설계

#### 이벤트 API (`/api/hackathon`)
| Method | Path | 설명 | 권한 |
|--------|------|------|------|
| GET | `/api/hackathon/events/active` | 현재 진행중 이벤트 조회 | 인증 |
| POST | `/api/hackathon/events` | 이벤트 생성 | ADMIN |
| PUT | `/api/hackathon/events/{id}` | 이벤트 수정 | ADMIN |

#### 팀 API
| Method | Path | 설명 | 권한 |
|--------|------|------|------|
| GET | `/api/hackathon/events/{eventId}/teams` | 팀 목록 조회 | 인증 |
| POST | `/api/hackathon/events/{eventId}/teams` | 팀 생성 | ADMIN |
| PUT | `/api/hackathon/teams/{id}` | 팀 정보 수정 | ADMIN |
| POST | `/api/hackathon/teams/{id}/members` | 팀원 추가 | ADMIN |
| DELETE | `/api/hackathon/teams/{id}/members/{userId}` | 팀원 제거 | ADMIN |

#### 채팅 API + WebSocket
| Method | Path | 설명 |
|--------|------|------|

## 참고 - 기존 패턴 재사용

- WebSocket: `usePureWebSocket` (회의실 채팅 패턴 동일)
- REST API: `architectureApi.ts` 패턴 동일
- 칸반 DnD: `@dnd-kit/core` (아키텍처 페이지 패턴)
- 블록 에디터: `TaskBlockEditor` (FAQ 내용 작성 시)
- 인증: `@AuthenticationPrincipal User user` + `isAdmin` 체크
