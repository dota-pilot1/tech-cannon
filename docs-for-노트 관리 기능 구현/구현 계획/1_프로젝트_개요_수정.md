# 노트 관리 기능 구현 계획 (수정)

## 📌 프로젝트 개요

### 목적
- 개발 지식을 체계적으로 정리하고 관리할 수 있는 2단계 노트 시스템 구현
- 1차: 카테고리별 주제 선택 페이지
- 2차: 선택한 주제의 노트 목록 + 본문 페이지

### 기존 문제점
❌ **현재 방식**: 각 주제별로 별도 메뉴 생성 (Frontend Note, Backend Note, ...)
- 메뉴가 너무 많아짐 (7개 드롭다운)
- 관리 복잡도 증가
- 확장성 부족

✅ **개선 방향**: 2단계 페이지 구조로 깔끔하게 정리
- 1차 페이지: 카테고리 선택 + 주제 카드 그리드
- 2차 페이지: 노트 목록 (좌측) + 노트 본문 (우측)

**구조:**
- 각 **카테고리**가 하나의 섹션

- 구분선
- 해당 카테고리의 **주제 카드들** (가로 그리드)
- 다음 카테고리 섹션...

**주제 카드:**
- 주제명 + 노트 개수 표시
- hover 효과
- 클릭 시 해당 주제 상세 페이지로 이동 (`/notes/frontend`)

- 코드 블록 syntax highlighting
- 이미지 표시
- 편집/삭제 버튼 (작성자만)

## 🗂️ 데이터베이스 설계

### 주요 테이블

#### 1. note_categories (카테고리)
```sql
CREATE TABLE note_categories (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,              -- 예: "Core", "Client/UX"
    icon VARCHAR(50),                        -- 예: "🧱", "🎨"
    order_num INT NOT NULL DEFAULT 0,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**샘플 데이터:**
```sql
INSERT INTO note_categories (name, icon, order_num) VALUES
('Core', '🧱', 1),
('Client / UX', '🎨', 2),
('Server / API', '🌐', 3),
('Infra 확장', '☁️', 4),
('시스템 / 확장', '⚙️', 5);
```

#### 2. note_topics (주제)
```sql
CREATE TABLE note_topics (
    id BIGSERIAL PRIMARY KEY,
    category_id BIGINT NOT NULL REFERENCES note_categories(id) ON DELETE CASCADE,
    name VARCHAR(100) NOT NULL,              -- 예: "Frontend", "Backend"
    description TEXT,                        -- 주제 설명
    order_num INT NOT NULL DEFAULT 0,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**샘플 데이터:**
```sql
-- Core 카테고리의 주제들
INSERT INTO note_topics (category_id, name, order_num) VALUES
((SELECT id FROM note_categories WHERE name = 'Core'), 'Frontend', 1),
((SELECT id FROM note_categories WHERE name = 'Core'), 'Backend', 2),
((SELECT id FROM note_categories WHERE name = 'Core'), 'Database', 3);

-- Client/UX 카테고리의 주제들
INSERT INTO note_topics (category_id, name, order_num) VALUES
((SELECT id FROM note_categories WHERE name = 'Client / UX'), 'Design (Figma, UX)', 1),
((SELECT id FROM note_categories WHERE name = 'Client / UX'), 'State Management', 2);
```

#### 3. notes (노트)
```sql
CREATE TABLE notes (
    id BIGSERIAL PRIMARY KEY,
    topic_id BIGINT NOT NULL REFERENCES note_topics(id) ON DELETE CASCADE,
    title VARCHAR(200) NOT NULL,             -- 노트 제목
    content TEXT,                            -- 노트 본문 (Markdown)
    author_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    is_public BOOLEAN NOT NULL DEFAULT false,
    view_count INT NOT NULL DEFAULT 0,
    order_num INT NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

#### 4. note_attachments (첨부파일)
```sql
CREATE TABLE note_attachments (
    id BIGSERIAL PRIMARY KEY,
    note_id BIGINT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    file_name VARCHAR(255) NOT NULL,
    file_url TEXT NOT NULL,                  -- S3 URL
    file_type VARCHAR(50),                   -- image, document, code
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

## 🎨 UI/UX 설계

### 화면 흐름
```
1. /notes 접속
   ↓
2. 카테고리 선택 (예: Core)
   ↓
3. 주제 카드 표시 (Frontend, Backend, Database)
   ↓
4. 주제 클릭 (예: Frontend)
   ↓
5. /notes/frontend 페이지로 이동
   ↓
6. 좌측: Frontend 노트 목록
   우측: 선택된 노트 본문 (또는 안내 메시지)
   ↓
7. 노트 선택 → 본문 표시
   ↓
8. [편집] 버튼 → Markdown 에디터 모드
```

### 라우팅
```
/notes                    → 1차 페이지 (카테고리 + 주제 카드)
/notes/:topic             → 2차 페이지 (노트 목록 + 본문)
/notes/:topic/:noteId     → 같은 2차 페이지 (특정 노트 선택됨)
```

예시:
- `/notes` → 노트 관리 메인
- `/notes/frontend` → Frontend 주제 페이지
- `/notes/frontend/15` → Frontend 주제 페이지 + 15번 노트 선택됨

## 📦 기술 스택

### Frontend
- React 19 + TypeScript
- TanStack Router (라우팅)
- TanStack Query (데이터 페칭)
- Tailwind CSS + shadcn/ui (UI 컴포넌트)
- `react-markdown` + `react-syntax-highlighter` (Markdown 렌더링)

### Backend
- Spring Boot 3 + MyBatis
- PostgreSQL
- AWS S3 (이미지 첨부파일)
